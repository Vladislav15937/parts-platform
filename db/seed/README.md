# Сборка справочников

Здесь собираются те справочники, которые нельзя завести руками в интерфейсе:
они наполняются миграцией, потому что общие для всех клиентов и меняются
с релизом, а не в течение дня.

| Что | Скрипт | Changeset |
|---|---|---|
| Марки, модели, поколения | `collect.py`, `gen_seed.py` | `catalog/009-vehicle-seed.sql` |
| Виды деталей и синонимы | `build_part_kinds.py` | `catalog/011-part-kinds.sql` |
| То же, по написаниям живого склада | `build_part_kinds_live2.py` | `catalog/013-part-kinds-live2.sql` |
| Русские написания марок и моделей | `build_vehicle_aliases.py` | `catalog/018-vehicle-aliases.sql` |

Ниже — про первый, самый большой; остальные объяснены в комментариях своих
скриптов и changeset'ов.

## Справочник машин

Марки, модели и поколения для `catalog.brand` / `model` / `generation`.
Без них продукт не работает: `donor.brand_id` — обязательное поле, то есть
машину в систему не занести.

## Откуда данные

Каталог Дрома. Источник выбран не произвольно: выгрузка идёт туда, и справочник,
собранный по чужому дереву, дал бы модели, которых площадка не знает.

Структура берётся из sitemap'ов, которые Дром публикует сам и перечисляет
в своём `robots.txt` — 28 файлов вместо десятков тысяч загрузок страниц:

```
catalog_firms_index.xml        → 308 марок
catalog_models_index.xml       → 4354 модели
catalog_generations_index.xml  → поколения (после схлопывания 12430)
```

Со страниц читаются только названия — по одной странице на марку, с паузой
в секунду, как просит `Crawl-Delay`. Слаг в адресе названия не даёт,
а «mark_ii» вместо «Mark II» в карточке детали приёмщик не узнает.

## Что важно знать про данные

**Поколение у нас — диапазон лет, а не тип кузова.** У Дрома одно поколение
разложено на записи по кузовам: у Camry 1982 года их четыре, и различаются они
только идентификатором. Схлопнуто по году начала — иначе в списке четыре
одинаковых «1982—1983», которые приёмщик не различит. Кузова живут
в `catalog.body_type`, и это отдельная задача.

**Год окончания выведен**, а не взят с сайта: это год начала следующего
поколения минус год. У последнего его нет, и это верно — модель ещё выпускается.

**Русское написание марки** взято из заголовка страницы. По нему приёмщик
выбирает машину, набрав «тойота» и не переключая раскладку, — это читает
`VehicleCatalogService`.

А вот **поиску по складу** одного `name_ru` мало, и полурусский поиск хуже
нерусского: у продавца, которому сработало «тойота», следом не находится
«камри», и он решает, что камри на складе нет. Поэтому для поиска заведён
отдельный словарь написаний — марка **и модель**, с ходовыми вариантами
(«Аутлендер» и «Оутлендер», «СРВ» и «ЦРВ»), — его собирает
`build_vehicle_aliases.py` по моделям живого склада. Словарь, а не
транслитерация: правило, выдающее одно написание, промахивается ровно там,
где человек написал второе, и промах молчаливый.

## Как обновить

```bash
cd db/seed
python3 collect.py     # скачивает и пишет brands/models/generations.csv
python3 gen_seed.py    # собирает 009-vehicle-seed.sql
cp 009-vehicle-seed.sql ../changelog/catalog/
```

Скачанное кэшируется в `pages/`, повторный запуск сеть не трогает.
Changeset'ы наполнения помечены `runOnChange`, поэтому обновлённый файл
накатывается поверх: `ON CONFLICT` правит имена и годы, ничего не удаляя.
Ссылка на запись в каталоге Дрома хранится в `generation.source_ref` — по ней
новые поколения отличаются от уже загруженных.
