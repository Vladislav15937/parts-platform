# Подключение клиента

Порядок шагов от пустой ячейки до первой позиции, уехавшей на Дром.
Написан для того дня, когда клиент рядом и вспоминать некогда.

Всё, что здесь есть, проверено на прогонном арендаторе «YARD Ткацкая» —
35 841 позиция, 440 машин. Замеры в скобках — оттуда же.

---

## До дня подключения

Три вещи не делаются за час, и без них день подключения упрётся в ожидание.

**Выгрузка из прежней системы — с колонкой «Выгружать».** Клиент запрашивает
её у Bazon сам. Без этой колонки флаг «выгружать» приходится угадывать,
а угадывание означает либо объявления на битые детали, либо пропавшие
объявления на хорошие.

**Письмо Дрому про API защищённых сделок.** Ключ `drom-api` они выдают
по запросу, публичного описания протокола нет. Пока ключа нет, заказы
с площадки заводятся руками — механизм для этого готов, и при появлении
ключа поменяется только то, кто зовёт `registerMarketplaceOrder`.

**Письмо Дрому про прайс-лист.** Разбор нашего XML на их стороне настраивает
их техспециалист. Там живой человек, и это не день.

Плюс от клиента: список филиалов и складов, коды ячеек (стеллажи, ряды),
список сотрудников с ролями.

---

## 1. Ячейка

Пилотных клиентов разложить по разным ячейкам. Десять компаний из одного
города общаются между собой: одна потерянная база — и сарафан работает против
вас необратимо.

```bash
cp .env.example .env          # секреты, домены, APP_CELL, APP_CELL_NUMBER
docker compose -f docker-compose.prod.yml up -d --build
ops/install-cron.sh           # бэкапы: ежедневно, проверка по понедельникам
```

Проверить до того, как в ячейке появится клиент:

- `https://<домен>/` открывается по https — без защищённого контекста
  не работает камера, то есть нет ни съёмки деталей, ни сканирования;
- тревога доходит: `docker stop <ячейка>-app-1`, через две минуты приходит
  сообщение в Telegram, `docker start` — приходит снятие;
- `ops/backup.sh && ops/verify-backup.sh` проходят целиком.

Ячейка, на которой это не проверено, отличается от проверенной только тем,
что вы об этом не знаете.

## 2. Арендатор

```bash
docker compose -f docker-compose.prod.yml exec app \
  curl -s -X POST http://localhost:8080/api/provisioning/tenants \
    -H 'Content-Type: application/json' \
    -d '{"token":"<APP_PROVISIONING_TOKEN>",
         "companyCode":"yardt",
         "companyName":"YARD Ткацкая",
         "ownerLogin":"vladelec",
         "ownerPassword":"<пароль>",
         "ownerName":"Иван"}'
```

Одна операция: запись в реестре, схема, миграции, владелец, филиал и первый
склад. Отвечает номером арендатора и именем схемы.

**Код компании клиент будет вводить при каждом входе** — короткий, латиницей,
без сюрпризов в раскладке. Позже он же станет поддоменом.

**Секрет провижининга выключается сразу после подключения** (пустое значение
в `.env`, перезапуск приложения). Забытый включённым, он даёт любому,
кто дошёл до управляющего контура, заводить схемы, пока не кончится диск.

---

## 3. Филиалы, склады, ячейки

Провижининг завёл один филиал и один склад — этого хватает, чтобы принять
деталь, но не хватает живому клиенту.

```
POST /api/organization/branches           филиал
POST /api/organization/warehouses         склад в филиале
POST /api/organization/warehouses/{id}/cells   ячейки списком
```

**Ячейки заводятся списком, а не по одной.** Стеллаж — это два-три десятка
адресов подряд, и по одному их не заведёт никто: коды уедут в примечание,
а поиск детали на полке вернётся к памяти кладовщика. Уже существующие
пропускаются, а не ломают запрос целиком.

**Кириллица в кодах ячеек проверяется здесь, а не на печати этикеток.**
Code128 не знает кириллицы вовсе. «А», «В», «Е», «К» переживают это — сканер
сводит их к латинице, — а «Б», «Г», «Д» двойника не имеют, и такой адрес
не отсканируется никогда. Экран этикеток такие адреса помечает и не даёт
выбрать. Переименовать десять полок в первый день дешевле, чем через месяц
объяснять кладовщику, почему сканер их не видит.

---

## 4. Сотрудники

```
POST /api/members    логин, пароль, имя, роль
```

Роли: `OWNER`, `MANAGER`, `STOREKEEPER`, `SELLER`, `VIEWER`.
Заводит сотрудников только владелец. Отчёты и выгрузки видит
владелец и менеджер: там зарплатная база смены и себестоимость.

Заводить до переноса не обязательно, но удобно: в день подключения продавцы
уже смогут посмотреть склад.

---

## 5. Перенос склада

Два файла из прежней системы — машины и товары:

```
POST /api/import/bazon
  donors=<выгрузка машин>.xlsx
  catalog=<выгрузка товаров>.xlsx
```

Вместе с позициями переезжают поставки, доноры, резервы по складам и флаг
«Выгружать». Повтор безопасен: товар узнаётся по своему коду из выгрузки,
машина — по своему, поставка — по паре «тип и номер».

Замерено: 35 841 позиция и 440 машин — 59 секунд первый раз, 32 повторный.
Файл на 24,7 МБ проходит (предел 64 МБ).

**Повтор — обычное действие, а не авария.** Если ответ не пришёл или пришёл
ошибкой, повторяйте: ключ идемпотентности защищает от второй копии склада.

**После переноса импортёр сам доводит справочник и карточки.** Ничего
дополнительно запускать не нужно.

## 6. Разбор наименований

Открыть вкладку «Наименования» — там число нераспознанных написаний.

На переехавшем клиенте после переноса их было 1 020 под 11 182 карточками —
треть склада без вида детали, то есть без категории, то есть не уедет
на площадку. После расширения справочника и разбора руками осталось 225
написаний под 1 658 карточками.

Что делать:

1. `POST /api/part-names/rematch` — пересопоставить по нынешнему справочнику.
   Справочник растёт с релизом, а написания клиента заведены раньше.
2. Разобрать сверху вниз: список отсортирован по числу позиций, и одно
   сопоставление правит сотни карточек разом (на прогоне «тросик ручного
   тормоза» → «Трос ручника» исправило 379).
3. Смотреть на строку **«Станет»** перед нажатием. Она показывает, каким
   станет заголовок карточки. Разница между верным сопоставлением и ложью
   в заголовке видна только там: «тросик ручного тормоза» → «Трос ручника»
   верно, «Знак аварийной остановки» → «Набор инструментов» — нет, а обе
   кнопки выглядят одинаково. Сопоставление правит сотни карточек и назад
   не откатывается.
4. Что не определяется по написанию — оставить. «Стекло» бывает лобовым,
   задним, двери и форточкой; эталон отправил бы деталь в чужую категорию,
   а это хуже нераспознанного: нераспознанное видно на экране, неверно
   распознанное — нет.

**Не откладывать на после первой выгрузки.** Позиция без категории на площадку
не уедет, и обнаружится это по пустому прайсу, а не по сообщению об ошибке.

## 7. Выгрузка на Дром

Экран «Выгрузки», владелец или менеджер.

1. Завести кабинет площадки: `POST /api/marketplace-accounts` — `marketplace`
   («DROM») и `title` (название прайса, оно же различает несколько прайсов
   одной площадки).
2. Задать отбор (`PUT /api/marketplace-accounts/{id}/filter`): цена,
   состояние, склады, виды деталей, марки. Пустое поле — «без ограничения»,
   а не «ничего»: выгрузка, у которой не заполнили цену, отдаёт весь склад.
   **Смотреть на счётчик позиций перед сохранением.** Ноль показывается
   ошибкой, а не числом: пустой прайс площадка примет молча, и объявления
   пропадут вместе с накопленными просмотрами, за которые и платят.
3. Получить постоянную ссылку: `POST /api/marketplace-accounts/{id}/feed-url`.
   Она вида `/feeds/drom/{код}/{токен}.xml` и работает без входа — площадка
   забирает прайс сама, cookie у её сервера нет и не будет.
4. Передать ссылку техспециалисту Дрома.

**Прайсов на одну площадку может быть несколько**, и различаются они отбором:
у живого клиента их пять — «новые», «низкая», «средняя», «высокая», «очень
высокая», — у каждого свой прайс-лист в кабинете и своя цена размещения.

**Смена ссылки останавливает выгрузку.** Старая перестаёт работать сразу,
новую в кабинет площадки прописывает их техспециалист руками. Поэтому это
отдельное действие, а не побочный эффект сохранения настроек.

Замерено: полный прайс на 35 841 позицию — 0,95 секунды, 16 МБ.

**Ключ кабинета** (`PUT /api/marketplace-accounts/{id}/credentials`) нужен
только для дельт по API защищённых сделок. Он шифруется и наружу не отдаётся
ни одним эндпоинтом: отсутствие метода «показать» — часть защиты.
Без `APP_CRYPTO_KEY` запись ключа отвечает ошибкой, а не пишет открытым
текстом молча.

## 8. Приёмка с телефона

Клиент открывает домен на телефоне и ставит на экран как приложение.

Проверить в первый же день, стоя на складе:

- вход работает и запоминается — приложение обязано открываться без связи;
- сканер находит ячейку по этикетке;
- фотография уходит в хранилище (она идёт мимо приложения, прямо в S3);
- деталь, занесённая в ангаре без связи, доезжает после возвращения связи.

**Очередь отправки — единственный путь работы к серверу.** Экран кладёт запись
и считает работу сделанной. Если что-то не доехало, оно лежит во вкладке
«Очередь» с пометкой, а не пропадает.

## 9. Первая неделя

Смотреть три вещи:

**Вкладка «Наименования».** Число должно падать, а не расти. Растёт — значит
приёмщики вводят написания, которых нет в справочнике, и их надо разбирать
по ходу, а не копить.

**Вкладка «Доставка».** Событие, брошенное роботом после пяти попыток, ждёт
человека. Пусто — хорошо.

**Тревоги в Telegram.** Молчание — это либо всё хорошо, либо тревоги
не настроены. Проверяется остановкой приложения на две минуты, и лучше
проверить, чем предполагать.

И один вопрос клиенту в конце недели: **заносится ли деталь быстрее, чем
в прежней системе.** Это главный продуктовый показатель, и меряется он
секундомером на складе, а не ощущением.

## Чего в пилоте не будет

**Фискализации по 54-ФЗ.** Начинается с договора с оператором и регистрации
кассы, а не с кода. Что готово и чего не делать раньше времени —
`docs/fiscal-54fz.md`.

**Авито.** Генератор фида есть, доводить его сейчас не нужно — решение
владельца продукта. Выгрузка на первое время только Дром.

**Биллинга.** На двух клиентах счёт выставляется руками.

**Интернет-магазина на поддомене.** Недели 17–24 по плану.
