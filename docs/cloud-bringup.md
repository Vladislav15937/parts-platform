# Подъём арендованного сервера под ячейку

Что сделать с голым VPS **до** `docs/deployment.md`. Тот рунбук начинается
с `cp .env.example .env` и предполагает, что на машине уже есть Docker, закрыт
firewall и настроены домены. Здесь — ровно этот промежуток: от «арендовал
сервер» до «можно запускать ячейку».

> **Честно о статусе.** Локальный путь (провижининг → перенос → продажа →
> прайс) в этой сессии пройден целиком. А вот подъём на **настоящей удалённой
> машине** не прогонялся ещё ни разу — это процедура с обоснованием, а не
> проверенный боем чек-лист. Первый реальный прогон почти наверняка что-то
> уточнит; правьте этот файл по факту. По той же причине здесь нет «замерено» —
> цифры даны как расчёт, а не как результат.

Дальше по тексту `docs/deployment.md` — «§деплой», `docs/onboarding.md` —
«§клиент».

---

## 0. Что арендовать

Расчёт под **одного** пилотного клиента масштаба «YARD Ткацкая» (35 841
позиция, 193 630 снимков ≈ 24 ГБ). Замеры ёмкости ячейки — §деплой, «Сколько
держит ячейка»; здесь — что из них следует для железа.

| Ресурс | Под одного клиента | Почему |
|---|---|---|
| vCPU | 4 | JVM плюс параллельный перенос фото; Postgres+Kafka+MinIO рядом |
| RAM | 8 ГБ (комфортно 16) | весь стек в контейнерах; `shared_buffers` должен вмещать рабочий набор активного клиента (§деплой) |
| SSD | **100 ГБ** | и это узкое место, см. ниже |
| Второй хост/бакет | для офсайта | копия бэкапа наружу (`ops/backup.sh`, шаг «Офсайт») |

**Диск считается так, и он кончается раньше памяти.** Снимки одного клиента —
24 ГБ, зеркало бэкапа рядом — ещё 24 ГБ, датированные дампы за 14 дней, база,
ОС, образы Docker, запас на рост склада. Итого **80–100 ГБ минимум**, и растёт
с каждой принятой деталью. Локально в этой сессии диск чуть не забился ровно
на переносе снимков. Офсайт живёт **вне** этой машины и в её 100 ГБ не входит.

**Одна ячейка на машину.** Порты 80 и 443 на хосте одни, второй терминатор
их не получит (§деплой, «Вторая ячейка»). Пилотных клиентов раскладывают
по разным серверам — десять разборок одного города общаются между собой,
и одна потерянная база работает против вас необратимо.

## 1. Домены — первыми, до всего

Ячейке нужны **два** имени, оба A-записью на IP сервера:

- `parts.<домен>` — приложение и PWA;
- `s3.<домен>` — хранилище фотографий.

**Именно два, и это не про красоту.** Телефон грузит снимок прямо в хранилище,
мимо приложения, по подписанной ссылке — а хост входит в подпись. Caddy
принимает оба домена на 443 и проксирует `s3.*` внутрь на MinIO
(`ops/Caddyfile`: `reverse_proxy minio:9000`). Открытого порта у MinIO наружу
нет — всё через терминатор.

**Записи должны существовать до запуска.** Caddy получает сертификаты сам,
а Let's Encrypt проверяет владение доменом запросом на него же: нет A-записи —
нет сертификата, нет сертификата — нет камеры (§деплой, «HTTPS»).

Проверить, что оба резолвятся в IP сервера:

```bash
dig +short parts.<домен> s3.<домен>
```

## 2. Базовая настройка хоста

Ubuntu LTS как основа (примеры под неё; на другой ОС — те же шаги, свои команды).
Всё под `sudo` от свежего пользователя, не под root по SSH.

**Пользователь и SSH.** Root по паролю — первое, что перебирают боты в первый же
час жизни сервера.

```bash
adduser deploy && usermod -aG sudo deploy
# скопировать свой публичный ключ пользователю deploy, затем в /etc/ssh/sshd_config:
#   PermitRootLogin no
#   PasswordAuthentication no
systemctl restart ssh
```

**Firewall — наружу только три порта.** Больше ничего публиковать не нужно:
приложение, база, хранилище, Kafka, Prometheus — всё на внутренней сети Docker
(`expose`, а не `ports`), pushgateway на loopback. Проверено по
`docker-compose.prod.yml`: единственный `ports:` наружу — у Caddy, 80 и 443.

```bash
ufw default deny incoming
ufw default allow outgoing
ufw allow 22/tcp          # SSH
ufw allow 80,443/tcp      # терминатор; 80 нужен Let's Encrypt для продления
ufw enable
```

Управляющий контур провижининга **порта не занимает**: клиента заводят изнутри
сети compose (`docker compose exec app wget … http://localhost:8080/…`, §клиент),
а снаружи `/api/provisioning` закрыт по адресам на самом Caddy. То есть
firewall его не касается — но проверить, что снаружи он отвечает 404, всё равно
надо (§клиент).

## 3. Docker

```bash
curl -fsSL https://get.docker.com | sh
usermod -aG docker deploy      # чтобы docker без sudo; перелогиниться
docker compose version         # плагин compose v2 идёт в комплекте
```

**Диск Docker'а — там же, где кончится место.** Тома (`pgdata`, `miniodata`)
и образы лежат в `/var/lib/docker`. Если у провайдера отдельный большой диск
смонтирован не в корень — перенесите туда `data-root`, иначе 24 ГБ снимков
лягут на системный раздел:

```json
// /etc/docker/daemon.json
{ "data-root": "/mnt/data/docker" }
```

## 4. rclone для офсайта

Бэкап умеет увозить копию наружу (`ops/backup.sh`, шаг «Офсайт»), но адрес
и доступ к удалённому хранилищу настраиваются здесь.

```bash
apt install -y rclone
rclone config                  # завести удалёнку: S3/B2-бакет или SFTP на второй хост
rclone lsd <имя>:              # проверить, что доступ есть
```

Потом в `.env` (§деплой) — `OFFSITE_REMOTE=<имя>:<путь>`. Ключи удалёнки лежат
в `~/.config/rclone/rclone.conf`; храните их среди секретов ячейки, отдельно
от самого бэкапа (§деплой, «Секреты ячейки»). Без офсайта гибель диска уносит
клиента вместе с локальной копией — единственный случай, от которого локальный
бэкап не спасает.

## 5. Забрать репозиторий и передать управление deployment.md

```bash
git clone <репозиторий> parts-platform && cd parts-platform
```

Дальше — целиком `docs/deployment.md`, по шагам: `cp .env.example .env`,
заполнить секреты, `docker compose -f docker-compose.prod.yml up -d --build`,
`ops/create-roles.sh`, перезапуск app под рабочей ролью, `ops/install-cron.sh`.

Что не забыть в `.env` (пустые в примере — обязательные): `DB_PASSWORD`,
`APP_CRYPTO_KEY`, `ACME_EMAIL`, `ALERT_TELEGRAM_CHAT_ID`, `APP_RUNTIME_ROLE`
и `APP_DDL_*`, `OFFSITE_REMOTE`, плюс домены `APP_DOMAIN`/`S3_DOMAIN`
и `PROVISIONING_ALLOW`. Каждую — зачем и что при потере — §деплой, «Секреты».

**Kafka на одном узле.** `min.insync.replicas=2` на одном брокере не соберётся.
Для пилота — либо профиль `local` (события in-memory, Kafka не нужна), либо
осознанно один узел. Второй узел и репликация — когда клиентов станет несколько
(§деплой, «Kafka»).

## 6. Готов ли сервер принять клиента

Пройти **до** того, как заведён первый арендатор. Часть проверок — из §клиент,
собраны здесь в один список; ячейка, на которой это не пройдено, отличается
от проверенной только тем, что вы об этом не знаете.

- [ ] `https://parts.<домен>/` открывается с доверенным сертификатом
      (не локальный CA), в браузере замок без предупреждения;
- [ ] **камера с телефона** работает на этом домене — без неё нет ни съёмки
      деталей, ни сканера ячеек и VIN, то есть нет половины продукта;
- [ ] в логе приложения при старте `INFO Журналы защищены`, а не
      `WARN … правятся прямым SQL` (§деплой, шаг 3);
- [ ] `curl -o /dev/null -w '%{http_code}' -X POST https://parts.<домен>/api/provisioning/tenants`
      отвечает **404** снаружи (управляющий контур закрыт по адресам);
- [ ] тревога доходит: `docker stop <ячейка>-app-1`, через ~2 минуты сообщение
      в Telegram, `docker start` — снятие (§клиент);
- [ ] число правил Prometheus совпадает с `grep -c 'alert:' ops/alerts.yml`
      (§клиент — Prometheus не перечитывает файл сам);
- [ ] `ops/backup.sh && ops/verify-backup.sh` проходят целиком;
- [ ] **офсайт уехал**: в выводе `backup.sh` строка `Офсайт: …`, а не
      предупреждение о незаданном `OFFSITE_REMOTE`; на удалёнке лежит сегодняшний
      `shared.dump`;
- [ ] firewall закрыт: `nmap` с другой машины показывает открытыми только
      22/80/443, а не 8080/9000/5432.

Прошли все — заводите первого клиента по `docs/onboarding.md`.

## Чего здесь нет намеренно

**Ansible/Terraform и автоматизация подъёма.** На одном-двух серверах это
компонент, который надо держать и который сам может сломаться на ровном месте.
Пока ячеек единицы, воспроизводимость даёт этот файл плюс `docker-compose`,
а не отдельный инструмент оркестрации. Повод вернуться — когда серверов станет
столько, что поднимать их руками начнёт ошибаться человек.

**Мониторинг хоста** (место на диске, нагрузка самой машины) сверх того, что
смотрит Prometheus за ячейкой. Диск — первый кандидат: снимки растут, и «место
кончилось» на разборке значит «фото не грузятся». Простейшее — алерт на
`node_exporter`; пока его нет, смотреть `df -h` глазами в первую неделю.
