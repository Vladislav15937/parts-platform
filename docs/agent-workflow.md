# Как вести работу

Этот файл про то, **как** работать, а не про то, что система делает. Предметное
знание — в корневом `CLAUDE.md` и памятках модулей; там же причины решений.
Здесь порядок, доказательства и запреты — то, что в памятках не написано,
потому что раньше передавалось голосом.

Читать до первой правки. Он короткий.

---

## Кого звать

Описания лежат в `.claude/agents/` и едут вместе с репозиторием — на другой
машине и у второго человека они те же.

| Агент | Для чего | Меняет код |
|---|---|---|
| `conductor` | Держит доску `tasks/`, раздаёт задачи, отмечает сделанное | нет |
| `researcher` | Смотрит систему-ориентир и нашу рядом, сценариями; отдаёт задачи | нет |
| `planner` | Режет цель на задачи размером в ветку, с критерием приёмки | нет |
| `coder` | Пишет и правит код по поставленной задаче | да |
| `sweep` | Сплошной перебор одного класса дефектов из `docs/defect-classes.md` | да |
| `migrator` | Единственный, кто трогает `db/changelog` — по одному за раз | да, схему |
| `live-run` | Живой прогон работающей системы; только смотрит и отчитывается | нет |
| `reviewer` | Независимая проверка готовой правки против этого договора | нет |
| `doc-check` | Сверяет утверждения памяток с кодом: имена, числа, «ни одного» | только факты |
| `ops` | Дежурный по боевой ячейке: тревоги, бэкапы, отставание схем | **нет, и не должен** |
| `triage` | Разбирает жалобу живого клиента: воспроизводит и находит причину | иногда |

Кто пишет код, обязан прочитать правила: `docs/java-rules.md` для бэкенда,
`docs/frontend-rules.md` для экранов. Это не стиль, а решения с ценой.

Разделение не формальность. `live-run` ничего не правит намеренно: смешав
поиск с починкой, некому будет сказать «до правки было так». `migrator` один,
потому что два номера changeset'а сходятся молча. `reviewer` читает диff
чужими глазами — своя правка всегда выглядит проверенной. `ops` не меняет
боевую ячейку вообще: там живые данные живого клиента, и ошибка там
не откатывается кодом. `researcher` не меняет **чужую** систему по той же
причине, только данные там ещё и не наши.

## Как это запускается

**Оркестратор — сессия, в которой сидит человек.** Не потому, что иначе нельзя:
агент запустить агента **может**, это проверено опытом — вложенный `Explore`
запустился без предупреждений, отработал за три секунды и вернул результат.
Ограничение стоит на **типе** агента, а не на глубине: у встроенных `Explore`
и `Plan` инструмент запуска убран явным перечислением, у `general-purpose` —
оставлен.

Из наших агентов запускать других могут `coder`, `sweep`, `migrator`
и `researcher` (наследуют все инструменты); `doc-check`, `live-run`, `ops`,
`planner`, `reviewer` и `triage` — нет, у них набор перечислен явно и запуска
там нет. Это и правильно: они проверяют и докладывают, а не распоряжаются.

**Почему хаб всё-таки один, хотя дерево возможно.** Отчёт снизу идёт через
цепочку и на каждом шаге сжимается: с третьего уровня до человека доходит
пересказ пересказа, а разбирать потом придётся первоисточник. Расход растёт
незаметно — пять агентов по пять это двадцать пять исполнителей, которых никто
не считал. И право слияния принадлежит сессии (см. ниже): агент, раздающий
работу, рано или поздно захочет и слить её результат.

Поэтому дерево здесь применяют в одном случае: когда исполнитель нашёл **много
однородного** и проверяет находки параллельно — `sweep`, нашедший семь мест,
может раздать их проверку. Раздавать **разную** работу — дело сессии.

```
человек  →  сессия  →  агенты (параллельно)
                    ←  отчёты
            слияние — по правилу ниже
```

`planner` не начальник, а такой же агент: он режет цель на задачи и отдаёт
очередь — и запускать он ничего не может, инструмента у него нет. Запускает
человек через сессию, сливает — тоже она.

**Агент, заведённый в сессии, доступен только со следующей.** Список агентов
загружается при старте; файл, положенный в `.claude/agents/` посреди работы,
эта сессия не увидит и ответит «agent type not found». Обход на один раз —
позвать общего агента и первой строкой дать ему прочитать нужное описание.
Поймано при первом же запуске `researcher`.

### Круг: разведка → доска → исполнители → снова разведка

`researcher` сверяет нашу систему с ориентиром и заводит задачи в `tasks/`.
`conductor` раздаёт свободные исполнителям и отмечает вернувшееся. Исполнитель
возвращается **после слияния в `main` с зелёным CI**, а не по открытому PR.
Круг закрывается, когда доска пуста, — и тогда зовут разведку снова.

**Доска — файлы, а не память.** Агенты не делят состояние, и между запусками
не остаётся ничего, кроме репозитория. Одна задача — один файл: пять
исполнителей, правящих общий список, дерутся на слиянии, а свой файл каждый
трогает один. Смотреть — `./tools/board.py`, он же ловит враньё доски.

**Круг не бесконечен и не должен быть.** «Повторить ориентир полностью» —
недостижимая цель: часть его возможностей нам недоступна (проценка работает
на агрегате по всем их клиентам), часть отвергнута осознанно. Конец круга —
пустая доска, а не «повторили всё».

### Что параллелится, а что нет

| Работа | Параллельно | Почему |
|---|---|---|
| Правка кода | **да**, каждый в своём git worktree — параметр `isolation: "worktree"` при запуске | иначе дерутся за файлы: один видит в своём `git status` чужое, и `git add -A` кладёт чужую работу в его ветку. Случилось на первом же круге |
| Живой прогон | **да**, каждый заводит свою компанию | система мультиарендная — изоляцию для проверок дал сам продукт |
| Перебор классов дефектов | **да**, разные классы | пересекаются редко; один файл на двоих — конфликт слияния |
| Сверка памяток | **да**, она только читает | ни с кем не спорит |
| Схема (`migrator`) | **нет, строго по одному** | два номера changeset сходятся молча, а всплывает у клиента |
| Разведка ориентира | **нет, по одному** | не из-за конфликтов: несколько агентов, долбящих чужой боевой кабинет, — это нагрузка на систему живого клиента |
| Дежурство по ячейке | по одному | там и так ничего не меняют |

Живая система одна: Postgres на 5432, приложение на 8080, Vite на 5173.
Второй экземпляр не поднять — но и не нужно: параллельные агенты заводят
**каждый свою компанию**, и данные друг друга они не видят.

Разумный заход — **три-пять агентов разом**: например три перебора по разным
классам, одна сверка памяток и один живой прогон на своей компании.

### Где узкие места

- **Сессия — воронка.** Каждый отчёт приходит в неё. Пять агентов нормально;
  пятьдесят задач за ночь упрутся не в агентов, а в того, кто их читает.
- **Слияние за человеком** — по правилу ниже.
- **Сессия должна быть жива.** Закрыли окно — всё встало.
- **Решения тоже за человеком.** Из двенадцати правок одной сессии первые
  пять — чистая починка дефектов — не потребовали ни одного решения,
  а все последующие потребовали. Переборы идут без человека; продуктовая
  работа — нет, и никакой агент этого не изменит.

## Прежде чем начать: зелёная main

```bash
./tools/can-start.sh
```

Красная `main` — стоп для всех. Следующая правка ляжет поверх поломки, её тесты
пройдут на сломанном основании, и разбирать придётся две ошибки вместо одной.
Ночью, когда никто не смотрит, так теряется вся смена.

Красную `main` **не обходят**: либо её чинят, либо откатывают слияние, которое
её уронило, — и это первая задача, а не своя.

`main` защищена: слить с красным CI нельзя, прямой пуш и force-push отбиты,
и правила действуют на владельца тоже. Обойти это можно, только сняв защиту
в настройках репозитория — то есть решением человека, а не походя.

---

## Цикл одной задачи

0. **`./tools/can-start.sh`** — не строим ли мы на сломанном. Красная `main`
   отменяет всё остальное.
1. **Ветка `feature/N`** от свежей `main`. Одна задача — одна ветка, даже если
   правка в три строки: ветка дешевле разбора «что из этого сломало сборку».
2. **Найти правило, а не симптом.** Почти всё, что выглядит ошибкой, нарушает
   записанное правило: «две поверхности обязаны находить одно и то же»,
   «внутреннее представление не показывают человеку». Правило подсказывает,
   где ещё та же ошибка — а она почти всегда не одна. Из девяти ошибок
   ночного прогона 3 сентября 2026 три оказались классами: код поставки
   в семи местах, `null` в четырёх сущностях, три пробела приёмки подряд.
3. **Тест, который падает до правки.** Не после — до. См. «Доказательства».
4. Правка.
5. **Полный набор**: `./mvnw -o test`, `cd frontend && npx vitest run`,
   `./db/check-changelog.py`, `./tools/endpoint-coverage.py`. Первый идёт
   десять минут и нужен целиком: правка в одном модуле ломает соседний
   регулярно — так нашлась склейка `ENDAS supply`, которую глаза пропустили.
6. **Живой прогон**, если правку видит человек: `./tools/dev-up.sh`, потом
   руками или через `. tools/api.sh`. Тесты не видят, что экран врёт.
7. **PR с доказательствами** (что нашёл, чем доказал, чего не тронул).
8. **Зелёный CI — и только тогда слияние.** Шесть задач, около четырёх минут.

## Кто и что может слить

Слияние — единственное необратимое действие в цикле: после него правка
становится основанием для чужой работы. Поэтому право на него разное.

**Сливается само** — при зелёном CI и выполненном доказательстве:

- починка дефекта, у которой есть тест, **упавший до правки** (проверено
  откатом, а не рассуждением);
- перебор класса дефектов, где каждая находка закрыта таким тестом;
- правка памятки, документа или комментария, не меняющая поведение;
- сверка фактов `doc-check`, где исправлены числа и имена;
- **слова на экране, состав колонок и умолчания — но только те, что задача
  описывает дословно.** Критерий приёмки называет нужную формулировку,
  порядок колонок или подставляемое значение — исполнитель их и делает,
  ничего не выбирая; расхождение с задачей ловит проверка. Задача говорит
  «сделать удобнее», «как в Bazon», «привести в порядок» — выбор остаётся
  за исполнителем, а значит правка уходит в нижнюю половину.

**Сливает дирижёр — после разбора кода**, не спрашивая человека:

- **всё, что трогает `db/changelog`**: схема, новые колонки, индексы, вьюхи;
- **всё, что трогает деньги и журналы**: оплаты, лицевой счёт, возвраты,
  `stock_movement`, `audit_log`;
- **удаление чего бы то ни было**: кода без вызывающих, колонок, файлов;
- всё остальное, что не попало в верхний список и не названо ниже.

Два условия, и оба обязательны: **зелёный CI** и **вердикт `reviewer`
«можно сливать»**. Разбор — не формальность и не вторая пара глаз ради
приличия: он устанавливает то, чего проверки не видят — падает ли тест
до правки, не разъехались ли две поверхности, не показано ли человеку
внутреннее представление, не решено ли за владельца продукта молча.
Вердикт «нельзя» или «доказательство не получено» означает возврат
исполнителю, а не слияние с оговоркой.

**Ждёт человека по-прежнему** — сколько бы ни было зелёных проверок
и что бы ни сказал разбор:

- **всё на боевой ячейке** и всё, что уходит наружу от имени клиента:
  накат схем живым клиентам, выкладка, письма, запросы к площадкам.
  Слияние в `main` — не выкладка, и обратный ход у него есть; у этого
  обратного хода нет;
- **решения о продукте, которых задача не содержит**: как назвать
  на экране, что подставлять умолчанием, брать ли деньги, что считать
  себестоимостью. Это не про качество кода, и разбор тут не судья;
- **любая правка, где доказательство не получилось**: тест не удалось
  заставить падать, живой прогон не воспроизвёл. Это не «почти готово»,
  а «непонятно, что сделано».

Сомневаетесь, к какой половине относится ваша правка, — она из второй.

**Почему дирижёр получил право слияния 6 сентября 2026.** До этого схема,
деньги, журналы и удаление ждали человека всегда — довод был «слияние
необратимо». Он неверен: необратима **выкладка**, а слияние в `main`
откатывается `revert`'ом, и накат схем живым клиентам у нас отдельный шаг
развёртывания, а не следствие слияния. Реальная цена ошибки в `main` —
красная ветка и час работы, а не потерянные данные клиента.

Зато цена ожидания оказалась настоящей: задача 0023 неделю стояла зелёной
и разобранной только потому, что писала в `stock_movement`. Человек в этой
роли не добавлял проверки — он нажимал кнопку.

Поэтому гарантию даёт теперь не подпись, а **разбор**: `reviewer` смотрит
именно то, ради чего кнопку и держали, — доказательство, разъехавшиеся
поверхности, решения, принятые молча. Это сильнее прежнего порядка,
а не слабее: раньше человек сливал зелёный PR, не открывая его.

За человеком осталось то, у чего обратного хода действительно нет,
и то, что разбор судить не вправе, — решения о продукте.

**Почему верхняя половина шире, чем была.** Сначала «слова на экране
и умолчания» стояли внизу без оговорок, и это правило написано было,
глядя на починку дефектов, — там оно верно. Но паритетные задачи по
определению меняют то, что видит человек: не меняли бы — их не стоило
бы заводить. В круге 5 сентября четыре исполнителя независимо довели
работу до зелёного PR и встали, все четверо сославшись на один и тот
же абзац; дирижёр сформулировал это так: «на доске почти нет задач,
которые не были бы про это». Правило, задуманное как редкий тормоз,
стало общим случаем и остановило круг целиком.

Граница теперь не в том, **что** правка трогает, а в том, **кто выбрал**.
Формулировку выбрал владелец продукта и записал в задачу — исполнитель
её переносит, и это работа по образцу. Формулировку выбирает исполнитель
— это решение о продукте, и оно за человеком, чем бы ни была зелена
проверка. Отсюда требование к тому, кто задачи заводит: **критерий
приёмки называет слова и умолчания дословно**, иначе задача уходит
ждать ответа вместо работы.

## Что считается доказательством

**Сломай и проверь.** Написав тест, верните код к прежнему поведению и
убедитесь, что тест **упал** — и упал с сообщением, по которому понятно, что
именно сломано. Из семи проверок, написанных за ночь 3 сентября, одна не упала:
«отказ не выдаётся за пустую партию» ждала отсутствия текста, а на первом же
тике экран показывал «Загружаем…» — ожидание считалось выполненным, и тест
зеленел на вырезанной ветке отказа. Зелёный тест, который не падает от поломки,
хуже отсутствующего: он создаёт уверенность.

**Живой прогон для всего, что видит человек.** Шесть из девяти ошибок той ночи
нашлись запуском, а не тестами: код поставки, мнимая правка себестоимости,
поколение дважды, дата в ISO, заголовок вкладки, «Везде». Тесты работают на
маленьком свежем складе, где эти ошибки не проявляются.

**Замер, а не рассуждение**, когда речь о скорости, объёме или порядке.
«Страницы теряют строки» видно только на складе, где цена повторяется у сотен
позиций; «поиск медленный» — только на десятках тысяч.

**Отдельно: не заводите находку, не проверив инструмент.** Трижды за ночь
казалось, что сломан вход, — ломалась автоматизация браузера. Прежде чем
писать «не работает», посмотрите в network-лог, ушёл ли запрос вообще.

## Чего не делать без человека

- **Миграции на живых арендаторах** и любые правки боевой базы.
- **Правка применённого changeset** — чек-сумма разъедется у всех накатанных.
  Это отбивает `db/check-changelog.py`, но и без него: только новый changeset.
- **Запросы к чужим боевым API** (Дром) с придуманными ключами. Дельты
  проверяются на пустом наборе кабинетов, а не на их сервере.
- **Удаление данных**: снимков, записей журналов, схем. Списание и отмена —
  через операции системы, а не `DELETE`.
- **Рассылка чего-либо наружу** от имени клиента.
- **`git push --force`**, переписывание истории, слияние с красным CI.
- **Смена видимости репозитория и секретов.**

Правило простое: то, что нельзя откатить кодом, требует человека.

## Схему трогает один

`db/changelog` правит ровно один исполнитель за раз. Два, взявшие следующий
свободный номер, дают конфликт, который git сливает молча, а всплывает он
у клиента, накатанного следующим. Целостность набора проверяет
`db/check-changelog.py` (номера, включения, неизменяемость выпущенного,
сохранность порядка) — но проверка ловит уже случившееся, а очередь его
предотвращает.

---

## Куда писать найденное

В памятку того модуля, где живёт код (`<модуль>/CLAUDE.md`). В корневой
`CLAUDE.md` — только если наступить можно из любого модуля: доступ к схеме,
транзакции, коды ответа наружу, тесты. Иначе корень прирастёт обратно
к четырёмстам килобайтам, и его снова перестанут читать целиком.

Запись объясняет **почему** и **чем заплачено**, а не что сделано: что сделано,
видно в диффе. Хорошая запись начинается с того, как ошибка выглядела
для человека.

---

## Описание системы обновляет тот, кто её изменил

Памятка модуля отвечает на вопрос «**почему** так сделано и чем заплачено».
Она не отвечает на вопрос «**что** система теперь умеет» — а именно из него
решают, что делать дальше, и именно им рассказывают переходящему клиенту,
что он получит.

Поэтому правка, добавляющая или меняющая возможность, обновляет **три места**,
и это не бюрократия — каждое читают разные люди в разные моменты:

| Куда | Что там пишут | Кто читает |
|---|---|---|
| `<модуль>/CLAUDE.md` | почему так, чем заплачено, где ловушка | тот, кто правит этот код |
| `CLAUDE.md`, «Состояние и что делать дальше» | что система умеет | тот, кто решает, что делать дальше |
| `docs/bazon-parity.md` §12 | то же в сравнении с ориентиром | тот, кто считает, догнали ли мы |

Плюс `docs/walkthrough.md`, если изменился шаг сквозного прогона: инструкция,
которую ни разу не прошли, врёт в трёх местах из девяти — проверено.

**Пример, ради которого правило и появилось.** Отметка о заборе прайса
и наценка ушли в `main`; памятка `publishing` про них знала, а корневой файл —
нет. Читающий его узнал бы, что выгрузки умеют ровно то же, что и месяц назад,
и заново завёл бы задачу на уже сделанное.

Обратное тоже верно: **правка, ничего не меняющая для человека**, — починка
внутренностей, ускорение, перестановка кода — в описание возможностей
не идёт. Туда пишут то, что видно снаружи.

## Ловушки инструментов, а не приложения

Каждая стоила времени; они повторяются.

- **Ссылка на элемент в браузере устаревает** после `form_input`: форма
  перерисовалась, нажатие уходит в никуда — и выглядит это как «кнопка
  не работает». Перечитывайте страницу перед нажатием; если сомневаетесь,
  жмите из самой страницы (`requestSubmit()`), а сломано ли приложение,
  спрашивайте у network-лога.
- **Координаты в скриншоте не равны координатам страницы**: окно масштабируется.
  Работайте по ссылкам на элементы, а не по пикселям.
- **Текстовый блок Java срезает пробелы по краям.** `… AND """ + expr` даёт
  `ANDCASE`, а блок с закрывающими кавычками на строке содержимого теряет весь
  отступ и даёт `ENDAS supply`. Подставляя выражение в SQL, пишите разделитель
  явной строкой: `+ " AS supply"`.
- **Новый агент недоступен в той сессии, где его завели.** Список грузится
  при старте: файл, положенный в `.claude/agents/` посреди работы, даёт
  «agent type not found». Либо начать новую сессию, либо на один раз позвать
  общего агента и первой строкой дать ему прочитать нужное описание.
- **Двоеточие в описании агента ломает его заголовок.** `description: Прогон:
  поднять и пройти` — это для YAML вложенное поле, а не текст, и файл
  не разбирается вовсе. Описания в `.claude/agents/*.md` берите в кавычки.
- **bash 3.2 из macOS** прихватывает многобайтовый символ в имя переменной:
  `«$COMPANY»` падает с «unbound variable». Пишите `${COMPANY}`.
- **Тесты требуют Docker** (Testcontainers поднимает свой Postgres), фронтендные
  — Node из nvm, а не системный. `./mvnw -o` работает без сети.
- **Не запускайте `db/verify.sh` рядом с приложением на той же базе**: одну базу
  мигрирует что-то одно.

## Как отчитываться

Три вещи, и все обязательны:

1. **Что нашёл** — как ошибка выглядит для человека, а не как называется в коде.
2. **Чем доказал** — что упало до правки и что прошло после.
3. **Чего не тронул и почему.** Решения о паритете, о продукте и о том,
   расширять ли объём, принимает владелец; агент их называет, а не принимает
   молча.

Не отчитывайтесь объёмом: «проверено 57 эндпоинтов» без находок — это не отчёт
о работе, а отчёт о том, что искали не там.
