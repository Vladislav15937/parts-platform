Хвост 0181. Та задача свела две половины сторожа `tools/image-pin-guard.py`
на переехавшем файле: `_plant()` и `check()` теперь говорят о нём одними
словами (`GONE_MSG`, «файл из списка не найден, сторож неполон»). Но сводила
она **один** список — `LOOKED`. Третья половина сторожа считает файлы своим
списком и на переехавшем молчит.

## Что не так

У сторожа три способа набрать файлы, и ведут они себя по-разному.

| Откуда список | Кто читает | Переехавший файл |
|---|---|---|
| `LOOKED` (9 файлов) | `check()`, `_plant()` | **красное**, `looked_missing()` называет файл |
| `SWEPT_YAML` + `SWEPT_DOCKERFILES` (8 имён) | `sweep()` через `swept_files()` | **молча пропущен** |
| `SWEPT_GLOBS` + обход `src/test/java` | там же | не бывает: набирается образцом |

Пропускает его одна строка в `sweep()`:

```python
for name in swept_files(root):
    path = root / name
    if not path.is_file():
        continue
```

Совсем слепы те имена из двух кортежей, которых нет в `LOOKED`, — их четыре:
`db/docker-compose.yml`, `.github/workflows/ci.yml`,
`.github/workflows/deploy.yml`, `Dockerfile`.

## Чем доказано

Прогонами в чистом дереве на голове `4bca3c0` (0181 и 0155 уже слиты),
по одному переименованию за раз, с возвратом файла на место:

| Переименован | Код возврата | Сообщений «сторож неполон» |
|---|---|---|
| `db/docker-compose.yml` | **0** | 0 |
| `.github/workflows/ci.yml` | **0** | 0 |
| `.github/workflows/deploy.yml` | **0** | 0 |
| `Dockerfile` | **0** | 0 |
| `docker-compose.yml` (он в `LOOKED`) | 1 | есть |
| `tools/mirror/mc.Dockerfile` (он в `LOOKED`) | 1 | есть |

Вывод при переименованном `ci.yml` не отличается от вывода на целом дереве
ни строкой и кончается зелёным утверждением:

```
  ✓ перебор образов: чужих — 11, у каждого названа причина
Копий адреса нет, тег закреплён, зеркало наше.
```

То есть сторож **утверждает, что копий адреса нет**, ровно в том случае,
когда он их не искал.

И вторая половина тоже молчит: `./tools/image-pin-guard.py --selftest`
при переименованном `ci.yml` проходит целиком, кодом 0, включая строки
«настоящее дерево проходит» и «список сторожа полон: файлов в нём 9».
Самопроверка собирает дерево из `LOOKED` (`_plant()`), а про кортежи перебора
не знает вовсе — так что случай 0181 («переехавший файл списка — красное»)
этот класс не покрывает.

## Почему это стоит задачи

Перебор — пятый и самый широкий вопрос сторожа: **каждый образ, который дерево
откуда-то тянет, либо наш, либо назван в `EXCUSED` с причиной**. Он же
единственный, кто ловит адрес зеркала, выписанный литералом **не** в compose
и не в тесте, — про это сказано в самом коде: «проверка выше смотрит только два
compose и три теста, а тянуть образ может и шаг прогона, и скрипт ячейки».

Значит переименованный `ci.yml` или `Dockerfile` — это шаг прогона и рецепт
боевого образа, которые больше не проверяет никто, при зелёном прогоне.
Сторож заведён после аварии 26 сентября 2026, когда пять копий одного адреса
стоили красной `main` у всех; слепое место возвращает ровно ту возможность,
против которой он поставлен, и молчит именно при переименовании — в том
единственном случае, когда копия и могла уехать незамеченной.

Класс наш и назван в 0181 дословно: **сторож, не краснеющий на дефекте, хуже
отсутствующего.** Здесь он вдобавок печатает зелёное утверждение о том, чего
не проверял.

## Как проверить, что сделано

1. **Возврат дефекта по каждому из четырёх файлов.** Переименовать
   `db/docker-compose.yml`, `.github/workflows/ci.yml`,
   `.github/workflows/deploy.yml`, `Dockerfile` — по одному за раз — и убедиться,
   что сторож **краснеет и называет файл словами**, а не проходит зелёным.
   Возврат файла на место возвращает зелёное.
2. **Три списка ведут себя одинаково, и это поведение названо.** Либо любой
   объявленный и не найденный файл — красное теми же словами, что `GONE_MSG`,
   либо перебор набирает файлы сам (образцом), и тогда в коде сказано, почему
   объявленного списка больше нет. Молчащий `sweep()` при краснеющем `check()` —
   не вариант ни в какую сторону.
3. **Зелёная строка не печатается там, где не смотрели.** «Копий адреса нет,
   тег закреплён, зеркало наше» и «перебор образов: чужих — N» не должны
   выводиться, когда часть объявленных файлов не прочитана.
4. **Самопроверка краснеет на этом дефекте.** Новый случай `--selftest`
   переименовывает файл из кортежей перебора **во временном дереве** (не
   в рабочем) и требует красного. Проверить обязательно **откатом**: с прежней
   логикой (`continue` на ненайденном) новый случай обязан падать, иначе
   он ничего не утверждает.
5. **Семь прежних случаев самопроверки целы** (плавающий тег, чужой реестр,
   копия в compose, копия в тесте, тег без суммы источника, чужой образ вне
   перечня, переехавший файл `LOOKED`) и настоящее дерево по-прежнему проходит.
6. **Чисел руками не писать.** Правило из 0181 действует и здесь: сколько
   файлов в списке — печатается из `len()`, а не словом. Сейчас в docstring
   `sweep()` и в описании числа нет — не завести его.

  `check()` (около 326) и `_plant()` (около 459).

  (`--selftest`, затем прогон по дереву).

  краснеет» и «перебор набирает файлы сам» — за исполнителем, при условии
  пункта 2.
