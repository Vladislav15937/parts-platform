## Что человек сможет

1. **Завести машину целиком одной формой** «Создание донора»: фотографии, номер донора (подставлен следующий), поставка, статус, стоимость, описание для клиента, заметка, марка, модель, кузов, год, поколение, рестайлинг, двигатель, руль, тип КПП, модель КПП, привод, цвет, комплектация, VIN, пробег, ссылка на видео.
2. **Исправить машину после заведения** (ошиблись годом, дописали пробег) в той же форме по кнопке «карандаш» в карточке машины.
3. Из карточки машины одним нажатием увидеть **её запчасти** («65 Запчастей — Посмотреть» ведёт в список склада, отобранный по этой машине), и из списка склада по номеру донора вернуться в машину.

Как часто: у клиента машины заводятся пачкой по приходу контейнера (поставки раз в 2–4 недели, в карточке поставки «Авто-доноры: N шт»; всего ≈530 доноров); правка и «что с неё снято» — ежедневно: по ним разборщик решает, что ещё снимать (**вывод**, частота правок снаружи не видна).

## Почему это важно

Машина — основа учёта: по ней считается окупаемость, наследуются руль, КПП, привод, цвет, комплектация. Если эти поля нечем ввести, а ошибку в годе нечем поправить, приёмщик заводит машину неполной, и все её детали наследуют пустоту.

## Что известно

### Что сейчас вместо этого

Экран «Машина» (`DonorScreen`): **восемь** полей — марка, модель (после выбора марки), год, поколение, кузов, двигатель, VIN, поставка, «Примечание»; остальное API принимает (`steering`, `driveType`, `transmissionType`, `transmissionModel`, `equipmentCode`, `color`, `mileageKm`), а экран не показывает — руль, коробка, привод, цвет, пробег, комплектация у новой машины пусты и нечем заполнить; они лежат только у перенесённых с Bazon и показываются на вкладке «Донор» у позиции (`PartDonorView`). **Правки машины после заведения нет вовсе**: `PUT /api/intake/donors/{id}` не написан (в таблице есть лишь «Где стоит», «В разбор», «Затраты», «Фото»). Рестайлинга у машины нет (только «Поколение»). Статус машины — закрытый перечень «Куплена / В разборе / Разобрана / Списана»; у Bazon статус — список, который ведёт клиент. «Запчастей с машины» в строке нет: чтобы увидеть детали донора, надо в складе отбирать колонку «Номер донора» руками.

### Как это у Bazon (видел)

* **Список «Автомобили-доноры»** (иконка «машина», `/references/carsrc/`): режимы «Справочник» / «Редактирование»; колонки `Номер донора`, `Превью`, `Поставка`, `Марка`, `Модель`, `Поколение`, `Рестайлинг`, `Кузов`, `Двигатель`, `Год выпуска`, `Цвет`, `Статус`, `Описание`, `Руль`, `Привод`, `Тип КПП`, `Модель КПП`, `VIN`, `Комплектация`, `Пробег`, `Заметка`. По умолчанию — **по номеру по убыванию** (511, 510, 509 …), 533 автомобиля, «Скачать таблицу».
* **«Добавить авто»** (режим «Редактирование») → окно **«Создание донора»**: «Фотографий нет» + «Добавить фотографии»; **«Общая информация»**: `Номер донора` — **подставлен 512** (следующий, жирным; строка «Изменить»), `Поставка` («– Не задано –», список с поиском, «+ Новая поставка»), `Статус` («– Не задано –»; значения списка — «В Японии», «В [город]»), `Стоимость`, `Описание (для клиента)`, `Заметка (для вас)`; **«Основные параметры»**: `Марка` (ввод с подсказкой из справочника: «toy» → «Toyota»), `Модель`, `Модель кузова`, `Год выпуска`, `Поколение`, `Рестайлинг` (два последних — из справочника по модели, при смене поколения рестайлинг сбрасывается: «Будет удалено»), `Модель двигателя`, `Расположение руля` («– Не задано –»), `Тип КПП` («– Не задано –»), `Модель КПП`, `Привод` («– Не задано –»), `Цвет`, `Комплектация`, `VIN`, `Пробег`, `Ссылка на видео`. Кнопки внизу «Создать донора» и «Отменить»; рядом с ними жёлтый счётчик «Изменён N параметр». Каждая строка — значение «—» и «Изменить», разделы сворачиваются стрелками ↑ ↓ «−». «Отменить» закрывает форму без вопроса и без следа (число машин осталось 533).
* **Карточка машины** (`/references/carsrc/NNN/`): сверху плитка «**65 Запчастей** · Посмотреть», затем строки `Номер донора`, `Поставка` («Поставка-пример | 30.09.26 | (XXX-26)»), `Статус`, `Стоимость`, `Марка`, `Модель`, `Модель кузова`, `Модель двигателя`, `Поколение` («1 пок., 1 рест. 2014—2020»), `Год выпуска`, `Расположение руля`, `КПП` («Вариатор, K312-08A» — тип и модель одной строкой), `Привод`, `Цвет`, `Комплектация`, `Пробег` (100000); справа фотографии машины (до девяти и больше), в шапке карандаш правки.
* **Наследование позицией** (видно по 300 001, донор 77): `Комплектация` позиции = «Правый руль, Вариатор, Передний, 500000» — **руль + тип КПП + привод + комплектация донора** через запятую; цвет «Черный (B20)», поколение, кузов, двигатель, год — как у донора. У нас то же собирается (`equipment`, «правый руль, АКПП, передний») — **отличие только регистром первой буквы и тем, что у нас пусто «Комплектация» у донора** (у нашей новой машины его нечем ввести — см. выше).

**Не видел:** откуда список статусов (два значения — «В Японии» и «В [город]» — и оба про место; задаёт ли клиент свои), что делает «Удалить» у донора с запчастями, влияет ли правка донора на уже заведённые позиции (в форме позиции поля машины под замком — 0365).

## Как сделать (для сборки)

1. Форма «Создание донора» — поля и порядок как выше; «Номер донора» подставлен (следующий свободный, как номер позиции), правится; обязательны — **только марка** (как сейчас) пока не видели обязательность Bazon; статус — выбор из списка клиента (**вопрос ниже**).
2. Правка: `PUT /api/intake/donors/{id}` теми же полями + форма «карандаш»; изменённая машина пишется в журнал действий (0325 уже ведёт `donor`).
3. Карточка машины — плитка «N запчастей / Посмотреть» (ссылка в склад с отбором по номеру донора), поколение и **рестайлинг** (при поколении без рестайлинга поле пусто).
4. Фото при создании (кнопка «Добавить фотографии» в форме), а не только после.
5. Стороны/КПП/привод — словарь в одном месте на сервере, экран получает слова (как `PartDonorView`).

## Как проверить, что сделано

1. Машина заведена со всеми полями формы (руль, КПП и её модель, привод, цвет, комплектация, пробег, видео); после приёмки с неё у позиции «Комплектация» = «Правый руль, АКПП, Передний, <комплектация>».
2. Ошибочный год исправлен «карандашом»; в журнале действий запись «Машина: год 2003 → 2004».
3. «N запчастей — Посмотреть» открывает склад с отбором по этой машине; число совпадает с числом строк.
4. Закрытая «Отменить» форма не оставляет машины.
5. Тест падает на прежнем коде: `PUT` по машине отвечает 405/404, поле «руль» на форме отсутствует.

6. **Номер донора — порядковый, шестнадцатеричного кода нет ни на одном экране** (дописано 30.10.2026 по живому прогону сессии: после 0366 у позиции «Номер товара» — число, а машина по-прежнему называется кодом `42CFB92CE21C`). Часть со схемой (`migrator`): колонка порядкового номера донора, «следующий» по умолчанию в форме «Создание донора» (правится), уникальность в пределах организации; у перенесённых с Bazon номер остаётся их (`legacy_code`), у заведённых у нас — следующий за наибольшим. Затем **везде, где машина названа кодом, — номер**: сообщение «Машина заведена: №…» (`DonorScreen`, сейчас `created.publicCode`), список «Машины» и отбор «Номер донора» в складе, плитка «N запчастей — Посмотреть», подпись выбора машины у позиции (`DonorPick`), журнал действий («Донор: 261 → 262» и подпись «Машина: …»), отчёты (`ReportsScreen`: цепочка `note ?? legacyCode ?? publicCode ?? donorId` — шестнадцатеричный код остаётся последним запасным и не должен выбираться у машин, у которых номер есть), этикетки и документы. Источник перебора: `DONOR_CODE` (`CatalogService`, `PartVehicle.donorCode("d.legacy_code, d.public_code")`) и все чтения `publicCode` донора под `frontend/src`. Публичный код донора как поле остаётся в базе и в выгрузках (как публичный код позиции после 0366), но на экране не показывается.
7. Перебор для п. 6: тест открывает каждый экран и ответ API, где называется машина, у донора, заведённого у нас, и не находит `[0-9A-F]{12}` в тексте; падает на прежнем коде.
