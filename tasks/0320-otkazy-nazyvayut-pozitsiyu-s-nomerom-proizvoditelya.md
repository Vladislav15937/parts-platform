## Ответ владельца — 18.10.2026

Вопрос был (задача 0318): формат позиции в отказах, которые собирает сервер, — «Наименование · состояние» (`PartCondition.named`).

Ответ дословно: «1 -б 2-а 4-a + номер производителя запчасти 5 - а 6-б 7-а 8-a с возможностью заводить без состояния»; к этому вопросу относится «4-a + номер производителя запчасти».

Следствие: отказ называет позицию **наименованием, словом состояния и номером производителя**. Пример: «Фара левая Toyota Camry · контрактная · 8414012530». **Если номера нет, его не печатают.**

## Ответ владельца — 18.10.2026 (второй набор вопросов)

Ответ дословно: «1 - б, у детали только один номер произвоителя - остальное - кросс номера. 2 - а. 3 - а, все правки через UI должны фиксироваться . 4 - а . 5 - а . 6 - в, с предвыбором прошлого выбора клиента но с возможностью изменить . 7 - а»; к этой задаче относится «7 - а».

Следствие: основной номер производителя добавляется **в строки списков** рядом со словом состояния (выдача продавца, корзина, состав сделки, выбор позиций на возврат, заказы с площадок) — например «Фара левая … · контрактная · 8414012530 · № 347 · 1 шт». Работа заведена: **0327**. Решение 0320 «берётся только основной (`is_primary`, `raw_number`), без основного номера нет» остаётся правилом и для списков.

## Ответ владельца — 18.10.2026 (подтверждение решения исполнителя)

Ответ дословно: «8-10 да» (вопросы 8–10 того же набора). К этой задаче относится вопрос 8: в отказах только основной номер; если основного нет, номера в тексте нет совсем, кросс-номер не подставляется. **Решение исполнителя 0320 (PR 461) подтверждено владельцем продукта 18.10.2026.**

## Что человек сможет

Продавец, получив отказ («нужно 2, свободно 1», «не принимали как ожидаемую»), видит, **какая именно** из похожих позиций кончилась: «Фара левая Toyota Camry» бывает в нескольких состояниях и с разными номерами, по наименованию и состоянию её не отличить, по номеру производителя — можно.

Как часто: отказ при нехватке остатка и при приёмке бывает несколько раз в неделю у каждого продавца; читается на месте, в разговоре с покупателем.

## Почему это важно

0318 добавила в отказы слово состояния; владелец считает, что для различения этого мало: запчасти опознают по номеру производителя. Без него продавец, видящий «Фара левая · б/у — нужно 2, свободно 1», снова ищет, какая из двух фар.

## Что известно

**Читал код, не запускал.** Все вызовы `PartCondition.named` на `main` 18.10.2026 (строки сдвигаются, искать по тексту):

| Место | Что за текст | Откуда берётся позиция |
|---|---|---|
| `SalesService` ~457 | «… — нужно N, свободно M» при нехватке | `requirePart` (сущность) |
| `SalesService` ~2348 `namedPart` | позиция в прочих отказах сделки | `requirePart` |
| `PreorderService` ~117, ~197–202 | отказы и записи предзаказов | `JdbcTemplate`, `SELECT title, condition FROM part` |
| `IntakeService` ~278, ~283 | «не заводили как ожидаемую», «ожидается по другой поставке» | `parts.findAllById` |

Номер производителя — в `part_oem` (основная строка `is_primary = true`, остальные — кросс-номера); приводится `OemNumbers` (0309). У позиции его может не быть.

### Что решает исполнитель (называет в PR)

* **Какой номер:** предложение — только основной (`is_primary`), в виде хранения для показа (`raw_number`, а не `normalized`, который ключ поиска). Основного нет — не печатать; кросс-номер вместо основного не подставлять.
* **Где собирается строка:** `PartCondition.named` про состояние и номера не знает. Предложение — одно место, где позиция называется в отказе, и все четыре места ходят через него; номера грузятся **одним запросом** на путь отказа, а не запросом на строку списка.
* **Строки-списки на экране.** Владелец сказал про отказы. Касается ли это строк-списков (состав сделки, корзина и т. п.), исполнитель сам не решает: если номер там уже стоит отдельным полем, строки не трогать и сказать в PR; если нет — вынести вопросом владельцу, не правя молча.
* **Журнал и отказы склада** (`StockNaming`, публичный код) — не здесь, это 0321.

### Требования

1. Все места таблицы называют позицию «Наименование · состояние · номер».
2. Нет номера — нет и последнего « · » (не «Фара · б/у · »). Нет состояния, но есть номер — «Фара · 8414012530» (без пустого слова). Нет ни того, ни другого — наименование как есть.
3. Отказ не несёт внутренних номеров строк базы (`InternalIdsNotShownTest`); номер производителя — не внутренний `id`.
4. Нет запроса на каждую строку: отказ с несколькими позициями загружает номера одним запросом.

## Как проверить, что сделано

1. Тест через HTTP на каждом месте таблицы: отказ называет позицию с номером; откатом (снять номер из метода) краснеет именно он.
2. Три случая: есть номер и состояние; есть состояние, нет номера; нет состояния — каждый с нужным текстом, без висящего разделителя.
3. Тест-перебор по `src/main/java`: все вызовы `PartCondition.named` идут через один метод; новое место не называет позицию по-своему.
4. Записи: `sales/CLAUDE.md`, `intake/CLAUDE.md`, `inventory/CLAUDE.md`; таблица §12 `docs/bazon-parity.md`.
