## Что человек сможет

Объявление клиента на Дроме читается **тем же текстом**, что у Bazon: его собственное примечание «Комментарий», откуда деталь снята, на что она подходит и его постоянная приписка про оплату. Ничего, чего клиент не писал и Bazon не писал («Состояние: контрактная.», «Номер производителя: …»), в объявление не приезжает.

Как часто: каждая позиция каждого прайса; описание читают все покупатели.

## Почему это важно

Решение владельца 19.10.2026 («всё должно быть идентично»). Наше собираемое описание («Снято с: Nissan X-Trail NT30 QR20DE. Номер производителя: 48950-8H300. Состояние: контрактная.») — вымысел относительно образца: строки «Номер производителя» нет ни у одной из 35 745 позиций четырёх файлов; «Состояние:» встречается 193 раза, и это слова клиента внутри его комментария («Состояние: …» у новых деталей), а не строка, которую система дописывает.

## Что известно — устройство описания Bazon (видел, `drom-yardt-parts.xml`, `drom-new-parts.xml`)

Содержимое `<description>` — в `CDATA`, **начинается переводом строки**, затем блоки через пустую строку (`\n\n`); пустой блок не пишется вместе со своим разделителем; конца строки после последнего блока нет:

1. **«Комментарий (для клиентов)»** карточки как набран, переводы строк внутри как набраны (в файле встречается `\r\n`): `С накладкой. Контракт. Без пробега по РФ.`. Нет — блока нет. У 18 358 позиций из 20 324 в `drom-yardt-parts.xml` блок есть.
2. **`Запчасть снята с: Марка Модель [Год] Кузов Двигатель`** — первые значения полей (см. 0335), год **после модели**, как в названии файла; без номера и без положения. Есть у позиций с «Донор не задан» тоже — берётся из полей Марка/Модель/…; у **новых** (1 724) — нет ни у одной; нет у позиций без машины (ремни без марки). Есть у 20 290 из 20 324 (нет у 34 — ремни и мелочь без марки).
3. **`<Вид> подходит:`** и дальше по строке на машину: `Марка Модель N поколение ГГГГ–ГГГГ [Платформа ](кузова, через, запятую)` + либо `, любой двигатель (коды, через, запятую)`, либо ` двигатель КОД (объём Б|Д)[, КОД (объём Б|Д)]`. Годы через **длинное тире** `–`, конец — `н.в.`; платформа — код вроде `T31`, `XU30`, `E120`. Пример: `Nissan X-Trail 2 поколение 2007–2015 T31 (T31, TNT31) двигатель QR25DE (2.5 Б)`. Вид — первым словом заголовка блока как в `partname`. Нет применимости («Применимость не задана» в карточке) — блока нет: 3 457 из 20 324 (у «новых» — 441 из 1 724). Самая длинная строка — 652 знака, самое длинное описание — 36 220.
4. **«Текстовый блок»** — в карточке выбор из именованных блоков (у позиции 88 487 выбран «Наличные»); в файле его текст дословно: `ОПЛАТА В МАГАЗИНЕ ТОЛЬКО НАЛИЧНЫМИ!` (17 853 из 20 324; у позиций с номерами выше 106 780 — по большей части нет; в более старых файлах `drom-sredniy-parts.xml` и `drom-vysokaya-parts.xml` блока нет совсем — его добавили позже).

**Чего у Bazon в описании нет:** номера производителя, кросс-номеров, состояния, положения, цены установки, видео, текста про резерв («Выгружать товары в резерве» включается отдельно — см. 0339), «ожидается поступление» (там же).

**У нас (прогон 19.10.2026, код читан):** `DromPriceWriter.descriptionOf` — если описание клиента пусто, собирает «Снято с: …» / «Подходит на: …» + «Расположение: …» + «Номер производителя: …» + «Состояние: …»; к описанию дописывает текстовый блок, строку про установку и «Видео: …», а в начало — приписку «ожидается поступление». Применимости в описании нет (она уходит тегами `brandcars`/`modelcars`/…). У перенесённых с Дрома позиций (0275) текст клиента дословно.

## Откуда взять «Подходит» — вопросы владельцу

Данные «Подходит» у Bazon идут из **их** справочника поколений: платформа, список кузовов поколения, двигатели с объёмом и топливом. У нас `catalog.generation` — только годы, `generation.code` пуст у всех 12 430 записей (`catalog/CLAUDE.md`), двигателей и объёмов в справочнике нет. Собрать строку «T31 (T31, TNT31) двигатель QR25DE (2.5 Б)» по нашим данным нельзя.

Вопрос: Как заполнять блок «Подходит»? (а) Для переносимых с Bazon позиций — взять готовый текст блока из файлов выгрузки Bazon, которые есть у клиента (в них он уже собран по каждой позиции), и хранить его текстом у позиции (поле `part_drom_card.applicability` под это уже есть, 0287); (б) для позиций, заведённых у нас, — строка из того, что у нас есть («Марка Модель N поколение ГГГГ–ГГГГ»), без платформы, кузовов и двигателей — то есть **не идентично**; (в) наполнить справочник Bazon-видом (кузова и двигатели по поколению) — отдельная большая работа; (г) блока нет. Рекомендация — (а) + (б).
Вопрос: «Текстовый блок» — именованные блоки (как у Bazon: «Наличные» → текст) или поле текста на позицию, как сейчас (`part.text_block`)? Рекомендация: именованные блоки с выбором в карточке; у переехавших позиций блок называется по тексту («Наличные» — единственный в образце), у нас сегодня текст копируется в каждую.

## Как сделать (для сборки)

* Писатель описания собирает ровно четыре блока и ничего другого; убираются `own()`, `append()` (кроме текстового блока), «Видео:», строка про установку (настройка выгрузки остаётся, но выключена по умолчанию, как у Bazon — «Добавлять информацию об установке к описанию»: выкл. у прайса №1).
* Начало — перевод строки; блоки через `\n\n`; конца нет.
* «Запчасть снята с:» — по полям позиции (марка, модель, год, кузов, двигатель — те же первые значения, что в 0335), у новых и у позиций без марки/модели блока нет.
* Применимость — по ответу владельца.
* «Ожидается поступление» и «в резерве» — приписки включаются **только** переключателями выгрузки (0339), по умолчанию выключены.

## Как проверить, что сделано

1. На девяти позициях из `docs/bazon-parity.md` («Обход 19.10.2026») описание начинается переводом строки, блоки идут в порядке выше, разделители — пустая строка, конца нет; нет «Номер производителя», «Состояние», «Расположение».
2. Позиция без комментария и без применимости: `\nЗапчасть снята с: …\n\nОПЛАТА В МАГАЗИНЕ ТОЛЬКО НАЛИЧНЫМИ!`; новая позиция без машины: только комментарий и текстовый блок.
3. Позиция без текстового блока — без последнего блока и без лишней пустой строки.
4. Позиция, перенесённая с Дрома (0275): по решению владельца (вопрос в 0335).
5. Записи: `publishing/CLAUDE.md` (историй «Описание собирается, если своего нет» — отметить заменённой), таблица §12.
