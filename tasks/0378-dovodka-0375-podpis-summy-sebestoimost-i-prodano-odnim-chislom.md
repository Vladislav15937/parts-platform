## Что человек сможет

Открыв итоги поставки, прочесть про сумму поступлений **слово «себестоимость»**, а не «на N руб.»: из подписи видно, что это цена, по которой пришло, а не розничная цена карточки. И сверить «Продано» с вкладкой «Продано» отчёта по этой же поставке — **числа совпадают**, в том числе когда позиция из нескольких штук продана частично (колесо одно из двух).

Как часто: каждый раз, когда владелец смотрит контейнер после продаж — раз в неделю–две на контейнер при сотне поставок; частично проданные позиции (комплекты, колёса, фары парой) на разборке — обычное дело, не редкость.

## Почему это важно

Владелец складывает итоги поставки и вкладки «Продано» глазами — окупилась ли партия. Сейчас два экрана одной поставки называют «Продано» два разных числа без пояснения (разбор PR 522, решение владельца 26.10.2026: «пусть говорит и нужно сделать правильно»). Подпись «на N руб.» читается как цена продажи.

## Что известно

### Что сейчас вместо этого (проверено по коду 26.10.2026, не живым прогоном)

* **Подпись.** `frontend/src/screens/SupplySummaryBlock.tsx`, строка вида `Выполнены — 2 (на 5 700 руб.)`; у «Авто-доноров» уже стоит «(себестоимость N руб.)». Сумма считается в `SupplySummaryService.receipts()` как `sum(qty * COALESCE(l.price, p.cost_price, 0))` по строкам документов поступления — то есть закупочная, а не розничная.
* **«Продано» в итогах** (`SupplySummaryService.goods()`): штуки по журналу движений, `-sum(qty_delta)` по `SALE` и `RETURN` — продажи минус возвраты.
* **«Продано» на вкладке** (`OriginReportService`, `reports/CLAUDE.md`, абзац «Сходятся они не всегда»): отбор `p.status = 'SOLD'`; частично проданная позиция остаётся `IN_STOCK` и в список вкладки не попадает. Расширение отбора до «продано хотя бы одно» в памятке названо нерешённым решением о деньгах на экране. Закреплено тестом `partiallySoldPartDivergesFromRevenue`, который фиксирует расхождение, а не равенство.
* **Единицы разные:** вкладка — строки (позиции) с подвалом «items · выручка», итоги — штуки. «Одно число» поэтому надо сначала назвать (см. вопрос).

### Как это у Bazon (видел 26.10.2026, кабинет клиента, только чтение)

Окно «Поставки» → строка → «Поставка Ontecо санкционка 7»: блок «Поступления» — «Черновики — 0 (на 0 руб.)», «Выполнены — 2 (на 0 руб.)», «Отменены — 0 (на 0 руб.)», «Всего — 2 (на 0 руб.)»; «Товары» — «Остаток — 211 шт.», «Продано — 35 шт.», «Списано — 0 шт.», «Всего — 246 шт.» (211 + 35 + 0 = 246); «Авто-доноры» — «Всего — 0 шт. (с/с 0 руб.)». Кнопки «Удалить», «Редактировать», «Закрыть».

* **Подпись суммы у них — «на N руб.»**, без слова «себестоимость»; в списке поступлений та же сумма стоит в колонке «Сумма» как «закупка+накладные» («0+0»). Слово «себестоимость» («с/с») у них только у авто-доноров. Подпись «себестоимость» — решение владельца, **отступление от оригинала по слову**, и оно намеренное.
* **Единицы у них — штуки, и сумма сходится:** остаток + продано + списано = всего (на виденной поставке). Как они считают проданное на **частично проданной** позиции — **не видел** (у виденной поставки на глаз частичных нет, и по окну этого не узнать); что у них «Продано» — штуки, а не позиции, видно по «шт.» и по сходимости суммы — это **вывод из одного примера**.
* Вкладки «Продано» в разрезе по поставке с тем же числом не сверял: окно поставки и отчёт сверить в одном заходе не удалось (кабинет отвечал «Превышен лимит запросов»).

### Связи

С **0375** (слита, PR 522): это её доводка, поведение и тесты оттуда. С **0360** (документ поступления): у суммы поступления появится «накладные расходы» — подпись «себестоимость» придётся перечитать, когда они появятся (у Bazon «закупка+накладные»).

## Вопрос владельцу продукта

Вопрос: «Продано» в итогах поставки и на вкладке «Продано» отчёта должно быть одним числом в штуках (продажи минус возвраты, как считает карточка поставки) — то есть вкладка начнёт показывать и позицию, проданную частично, колесо одно из двух, — так?

Что стоит за вопросом. Ответ 26.10 велит «сделать правильно (одно число на обоих экранах)», но не называет, **какое**. По коду и по Bazon правильнее число в штуках из журнала: оно сходится с «остаток + продано + списано = всего» и совпадает с выручкой окупаемости, а вкладка сейчас её недосчитывает. Но чтобы совпали экраны, меняется вкладка («Продано» в разрезе по машине и по поставке), а отбор вкладки — решение о деньгах на экране, которое в `reports/CLAUDE.md` прямо отдано владельцу. Ответ «да» разрешает правку вкладки; ответ «нет» — оставить вкладку и подписать расхождение на экране итогов (другая задача по объёму).

## Как проверить, что сделано

Критерий исполнимый только после ответа «да» на вопрос выше; до того задача не раздаётся.

1. **Подпись.** Итоги поставки показывают «Выполнены — 2 (себестоимость 5 700 руб.)» (и так для «Черновики», «Отменены», «Всего»); строки «на N руб.» нет нигде. Тест на `SupplySummaryBlock`/`supplySummary.test.tsx` падает на прежнем коде: ждёт «себестоимость», получает «на 5 700 руб.».
2. **Одно число.** Поставка с позицией из двух колёс, проданной одним: «Продано» в итогах и подвал/число проданного на вкладке «Продано» отчёта по поставке дают **1 шт. / ту же сумму**; позиция на вкладке есть в списке. Тест через HTTP на схеме с собственным номером падает на прежнем коде (вкладка 0, итоги 1) — `partiallySoldPartDivergesFromRevenue` при этом **переписывается** с «фиксирует расхождение» на «числа равны», а не удаляется.
3. **Вкладка «Продано» в разрезе по машине** показывает то же (одна выборка с поставкой), иначе число разъедется на соседнем экране.
4. **Не сломано:** подвал вкладки по-прежнему сходится с `revenue` окупаемости; «остаток + продано + списано = всего» на поставке без пересчётов.
5. Памятки `reports/CLAUDE.md` (абзац про расхождение) и `intake/CLAUDE.md` (раздел «Итоги поставки на её строке») поправлены: расхождение больше не «известное».

Не проверено у нас живым прогоном: что именно видит человек на экране «Отчёты → по поставке» с частично проданной позицией — вывод сделан по коду и по памятке.
