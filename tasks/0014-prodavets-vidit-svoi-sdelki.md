## Что человек сможет

Открыть список сделок, которые ещё не выданы, и найти нужную по номеру
сделки или по номеру детали — а не только по имени клиента.

## Почему это важно

Проверено у нас, ролью `prodavec` на `proba`. На экране «Продажа» есть
ровно одна дорога к чужой сделке — ссылка «Найти сделку клиента», и она
спрашивает **только клиента** («имя или телефон»). Списка нет. Продавец,
вышедший на смену, не видит ни что отложено вчера, ни что просрочено,
ни сколько сделок висит на нём самом.

Два повседневных случая ломаются оба:

- **«Я вчера у вас откладывал, фамилия Петров»** — работает, если фамилия
  записана так же, как её сейчас произнесли. Записывал другой продавец.
- **«Мне звонили, деталь номер 111 157»** — не работает вовсе. Найти
  сделку по товару у нас нечем.

У ориентира раздел «Сделки» устроен воронкой слева — **Новые (2) ·
В работе (74) · Выданные · Отменённые · Все сделки** — и тремя
представлениями сверху: **Списком · По товарам · По статусам**.
«По товарам» — те же сделки, развёрнутые до позиций, с колонками
«Номер товара», «Наименование», «Статус товара»; по колонке «Номер товара»
работает тот же отбор, что и везде. То есть «в какой сделке лежит деталь
111 157» — это один отбор по колонке.

## Что сделать

1. У продавца появляется список сделок с воронкой по состоянию:
   **Отложенные · Выданные · Отменённые · Все**. По умолчанию открыты
   отложенные — это то, что требует действия.
2. Строка списка: номер и дата · клиент · сумма · оплачено · состояние
   и срок резерва (см. задачу 0012) · ответственный.
3. Поиск по списку: по номеру сделки, по клиенту и **по номеру
   (публичному коду) детали**.
4. Отбор «мои» / «все» — продавец чаще ищет своё, но чужое ему тоже нужно:
   возвращают не тому, кто продавал.

## Как проверить, что сделано

1. Продавец открывает список — видит отложенные сделки, свои и чужие,
   свежие сверху.
2. Поиск по номеру сделки «8» открывает сделку № 8.
3. Поиск по публичному коду детали из сделки № 8 находит сделку № 8.
   Это главная проверка — сейчас такого пути нет вовсе.
4. Код детали, которой нет ни в одной сделке, — «Ничего не найдено»
   словами.
5. Выданная сделка в воронке «Выданные», отменённая — в «Отменённых»,
   и обе видны в «Все».
6. Продавец не видит того, чего ему не положено: проверить, что список
   не отдаёт себестоимость и маржу (они в отчётах владельца).

## Что известно

`SalesController` уже отдаёт сделку по идентификатору и по клиенту;
списочного эндпоинта с отбором по состоянию нет — его придётся завести,
и по правилу из корневого `CLAUDE.md` **эндпоинт без экрана не считается
сделанным**: `tools/endpoint-coverage.py` завалит CI, пока экран не зовёт
новый путь.

Индексы: `deal_manager_ix (manager_id, closed_at DESC)` уже есть — выборка
«мои закрытые» дешёвая. Для «отложенных» есть `deal_reserved_until_ix`
с условием `status = 'RESERVED'`.

Поиск сделки по коду детали идёт через `deal_item` → `part.public_code`;
проверить план на складе в 35 тысяч позиций, а не на `proba` со 195.
