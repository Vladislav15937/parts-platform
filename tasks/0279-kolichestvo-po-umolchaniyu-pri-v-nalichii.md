## Что человек сможет

Загрузить файл переноса, в котором количества нет (у Дрома на карточке только «В наличии»), и получить позиции по одной штуке — а не отчёт «пропущено 2 897: нет количества». Количество, которое клиент знает, из файла по-прежнему читается.

## Почему это важно

«мы должны повторить объявление клиента на сто процентов. Со всеми фото, со всеми описаниями клиента и со всеми полями что есть. Это обязательно. И именно в том виде как это выглядит у него» — владелец продукта, 13.10.2026, в поручении разведки; записано здесь. Сейчас импорт требует количество: `ColumnMapping.missingRequired` не пускает загрузку без колонки, а строка с пустым или нулевым количеством пропускается со словами «нет количества» (`ExcelWarehouseImporter.parse`). Публичная карточка Дрома количества **не показывает**; у позиций «2шт» в заголовке («Амортизатор передний 2шт» — «цена за пару») это текст, не поле. Парсер не может положить в файл число, которого на странице нет. Результат без правки — либо парсер придумывает «1» молча (ложь о складе), либо импорт ничего не заводит.

Один раз на клиента, но блокирует перенос целиком.

## Как проверить, что сделано

1. На экране «Импорт» при отсутствии колонки количества показано: «Количества в файле нет — каждая позиция заведётся по 1 шт.» и кнопка «Загрузить» доступна. Слова — предложение разведки, исполнитель вправе поправить, но обязан **сказать человеку** (тихая подстановка запрещена: см. `ColumnMapping`, «догадка показывается человеку»).
2. Если колонка есть, а в строке пусто — тот же умолчанный «1» с пометкой в отчёте, **не** пропуск; «0» остаётся пропуском («нет количества» — правда про строку «позиции нет»).
3. Для переноса с Дрома колонка «Наличие» = «В наличии» → 1; иное значение дословно → пропуск строки со словом «не в наличии».
4. Тест: файл без колонки количества → N позиций с остатком 1; файл с нулём → пропуск; файл с «3» → три.

## Что известно

**Видели:** все 7 карточек — «Наличие товара в Барнауле: В наличии», количества нет. Заголовок бывает с «2шт».

**Решение, которое не принимаем:** считать «2шт» из заголовка количеством. Это текст клиента, а не поле; разбор вида «шт» дал бы 2 для «Амортизатор передний 2шт» (верно) и 1 для «цена за пару» (там две штуки по смыслу, но в заголовке «2шт» нет). Клиент после переноса подправит остатки сам; у нас есть пересчёт по документам (`inventory`).


## Решение владельца продукта 13.10.2026 по вопросам исполнителя

Владелец на вопросы из PR (в чате сессии), дословно: «остальное должно быть как в дроме у клиента». Следствия, записанные сессией:
- **Строка без «Наличия» или не «В наличии».** Как у клиента на Дроме: объявление на Дроме — это товар в продаже; в полном файле клиента (2 897 строк) «Наличие» заполнено у всех. Поведение исполнителя («В наличии» → 1 шт., иное значение или пусто → строка пропускается с названной причиной) этому не противоречит и остаётся.
