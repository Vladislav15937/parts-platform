## Что человек сможет

Найдя «фара», сузить список отбором по марке, модели, году, стороне,
складу и состоянию — не угадывая формулировку запроса. И отсортировать
по цене.

## Почему это важно

Проверено у нас, ролью `prodavec` на `proba`: запрос «фара» даёт

> Показаны первые 50 из 181 — уточните запрос, иначе нужная деталь может
> остаться за списком.

и **уточнять нечем**: поле одно, отбора нет, сортировки нет. Все 50 строк
на экране — «Фара Toyota Camry 2007 (б/у)» по 1 500 ₽, отличаются только
кодом. Продавец, которому по телефону сказали «фара на Камри 2007, левая»,
должен либо угадать, какими словами это записано на складе, либо листать.

У ориентира это же место устроено иначе, и разница не косметическая: список
товаров — таблица, **у каждой колонки свой отбор, который открывается
нажатием на её заголовок** и превращает заголовок в поле ввода. Отбор
показан плашкой в самой шапке колонки (`Запчасть "бампер"`), а слева
от таблицы стоит кнопка «Сбросить фильтры». 212 «бамперов» разбираются
за одно нажатие по колонке «Марка».

Это самое частое действие в системе — десятки раз в день.

## Что сделать

Список результатов поиска продавца получает отбор по колонкам. Минимальный
набор, покрывающий телефонный разговор:

| Отбор | Тип | Откуда значения |
|---|---|---|
| Марка | выбор из списка | марки, встречающиеся в найденном |
| Модель | выбор из списка | модели найденной марки |
| Год выпуска | от–до | |
| Сторона | Любой / Левый / Правый | `part.side` |
| Перед/зад | Любой / Передний / Задний | `part.position` |
| Склад | выбор из списка | склады арендатора |
| Состояние | выбор из списка | градации оценки |
| Цена | от–до | |

Сортировка — по цене (в обе стороны) и по дате приёмки.

Отбор применяется **к запросу в базу**, а не к 50 уже показанным строкам:
иначе «фара + Nissan» не найдёт ничего, хотя ниссановские фары на складе есть.
Это и есть суть — 50 из 181 сейчас режутся до того, как продавец успел сказать
марку.

Счётчик обновляется: «Найдено 6» вместо «первые 50 из 181».

## Как проверить, что сделано

1. Запрос «фара» на `proba` (181 позиция) — виден счётчик и элементы отбора.
2. Выбрать марку, которой в первых 50 строках нет вовсе, — позиции находятся.
   Это главная проверка: она отличает отбор в базе от отбора по показанному.
3. Отбор «Сторона: Левый» — остаются только левые; снять — возвращаются все.
4. Два отбора вместе (марка + год) сужают, а не заменяют друг друга.
5. Сортировка по цене возрастанию и убыванию, при включённом отборе.
6. Отбор, под который ничего не подходит, — «Ничего не найдено» словами,
   а не пустой экран.
7. Сброс отбора одним действием.

## Что известно

Поиск продавца идёт через репозиторий (не через `JdbcTemplate` витрины) —
см. запись про перегрузку `list(...)` без `@Transactional` в корневом
`CLAUDE.md`; при добавлении отбора не повторить её.

Полнотекстовый вектор — выражение в запросе с GIN-индексом, не колонка.
Отбор по маркам и моделям добавляется к нему условиями, не заменяет его.

Сколько именно отборов делать сразу — решать исполнителю по цене: набор
выше отсортирован по тому, что чаще звучит в телефонном разговоре.
Марка и сторона важнее прочего.
