# Фронтенд PartsFlow

Одно приложение на все роли: приёмка с телефона, рабочее место продавца,
витрина склада владельца, отчёты, выгрузки, этикетки. Решения по офлайн-части —
`../docs/pwa-intake-plan.md`, остальное — `../CLAUDE.md`.

## Запуск

Версия Node зафиксирована в `.nvmrc` — 22 LTS. nvm поставлен через brew,
и ему нужны две строки в `~/.zshrc`, иначе `nvm` не найдётся в новой оболочке:

```bash
export NVM_DIR="$HOME/.nvm"
[ -s /opt/homebrew/opt/nvm/nvm.sh ] && . /opt/homebrew/opt/nvm/nvm.sh
```

Дальше обычное:

```bash
nvm use              # берёт версию из .nvmrc
npm install
npm run dev          # http://localhost:5173
npm test             # vitest, 286 тестов
npm run build        # tsc --noEmit + vite build, то же гоняет CI
```

Бэкенд должен работать на `:8080` — Vite проксирует на него `/api`. Прокси
обязателен, а не удобен: сессия живёт в cookie, а CSRF-токен приложение читает
из cookie скриптом, и то и другое работает только на одном источнике. В бою
фронтенд собирается внутрь jar и отдаётся тем же приложением — по той же
причине.

## Что здесь есть

Семнадцать вкладок рельса слева (`HomeScreen`): приёмка, машины, продажа,
заказы с площадок, склад, шины и диски, пересчёт, очередь отправки, загрузка
и переезд, разбор наименований, отчёты, выгрузки, доставка событий, этикетки,
сотрудники, склады, справочники. Плюс то, что открывается поверх и адресом
не имеет: карточка позиции с историей и донором, форма правки, правка
списком, меню колонки, подбор машины, ссылка клиенту на его сделку. Что кому показывать, решает роль:
«Просмотр» не видит того, чего не может, — экран, зовущий сервер на отказ,
хуже отсутствующего.

Плотность переключается шириной экрана: до 900 пикселей всё крупное (цели
48 пикселей — приёмщик работает стоя и в перчатках), дальше кабинетная
плотность и рельс во всю высоту.

## Куда смотреть в первую очередь

**`src/api/client.ts`** — деление ошибок на постоянные, временные и «сессия
потеряна». На нём стоит очередь отправки: повторять можно только временные,
иначе одна битая запись забьёт очередь вечными повторами. Ради этого
различения на бэкенде есть `ApiExceptionHandler`. Оттуда же уходит событие
`SESSION_LOST`: 401 на обычном запросе означает «войдите заново», и сказать
об этом больше некому.

**`src/outbox/`** — очередь отправки в IndexedDB, единственный путь работы
приёмщика к серверу. Три правила: запись не удаляется до подтверждения,
повторяются только временные ошибки, потеря сессии останавливает проход
целиком. Запись помнит компанию, в которой поставлена, и в чужой сессии
не отправляется.

**`public/sw.js`** — API не кэшируется никогда. Закэшированный ответ склада
означает, что продавец видит деталь, которой нет. Поэтому Service Worker
написан руками, а не сгенерирован плагином: запрет должен быть виден.

Тесты — vitest в jsdom, IndexedDB подменяется `fake-indexeddb`: настоящее
поведение хранилища с транзакциями и версиями схемы, а не заглушка с Map.
Половина ошибок в работе с IndexedDB — это как раз транзакции.

## Чего здесь нет намеренно

- **Роутера.** Внутренний переход — это вкладка рельса, а не адрес: приёмщик
  не набирает URL, а приложение обязано открываться там, где его закрыли.
  Единственный разбор пути в `App.tsx` — ссылка клиенту на его сделку
  (`/s/{компания}/{токен}`), она открывается без входа.
- **Библиотеки состояния.** Данные экрана живут в самом экране, общее —
  сессия и очередь. `useState` и два контекста хватает.
- **Иконок в манифесте.** Нужны настоящие, а не заглушки: браузер
  отказывается ставить приложение с битыми иконками, и лучше пустой список,
  чем ссылки в никуда.
- **Кэша под продажу.** Приёмка построена на том, что связи нет, продажа —
  наоборот: закэшированный остаток это деталь, которой уже нет, у продавца
  на экране. Нет связи — вкладка продажи её и показывает.
